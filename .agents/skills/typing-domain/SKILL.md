# 타자 연습 도메인

입력과 결과 사이의 규칙을 바꾸는 작업에 사용한다. PR 상태와 버전은 [typing-slice-workflow](../typing-slice-workflow/SKILL.md)를 따른다.

## 필요한 입력

- 현재 사용자 요청 또는 GitHub 이슈·PR의 완료 조건.
- [docs/PROJECT-SPEC.md](../../../docs/PROJECT-SPEC.md)의 관련 사용자 동작과 제약.
- 관련 세션 타입, 입력 경계, 콘텐츠 또는 저장 스키마와 재현 절차.

## 작업 순서

1. 적용 모드, 유효한 시작 상태, 받아들일 이벤트와 관찰할 결과를 정한다. 예를 들어 한글 IME에서 조합 확정에 쓴 Enter는 현재 조합만 확정하고 다음 Enter가 제시문을 제출한다.
2. 도메인 제약을 데이터와 상태 타입에 반영한다. 점수와 상태 전이 함수에 확정 입력·시각·난수를 값으로 넘겨 같은 입력에서 같은 결과를 얻는다. 화면 갱신, 초점 이동, 실제 시계, 파일 입출력과 저장은 도메인 밖에서 처리한다.
3. 한글 입력을 바꾸면 조합 중 표시와 확정 값을 나눈다. 이벤트 순서가 달라져도 입력이 두 번 채점되지 않는지, NFC 정규화와 문자소 단위 비교가 오타 위치·길이와 일치하는지 확인한다.
4. 채점 변경은 정상 완료와 오타·수정·공백·초과 입력을 다룬다. 저장 변경은 새로고침, 손상되거나 미지원인 스키마, 중복 완료, 기존 데이터 보존, 쓰기 실패 뒤에도 연습이 계속되는지 다룬다.
5. 도메인 변경은 관련 순수 함수와 화면 경계에서 확인한다. IME 변경은 실제 OS 한국어 입력기로 확인한 환경과 미확인 환경을 구분한다. 문서 전용 변경은 코드 테스트·CI 대신 제품 명세와 문서 간 일관성을 확인한다.

## 산출물

변경 코드와 확인 근거를 같은 이슈의 PR에 남긴다. 사용자 동작 또는 불변식이 바뀌면 현재 제품 계약을 갱신한다. 저장이 막힌 경우 결과 화면이 보인다고 저장 성공으로 기록하지 않는다.
